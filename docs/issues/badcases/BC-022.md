# BC-022 — Current-build locomotion can run at near-zero velocity

- Status: open
- Classification: current-confirmed
- ISSUE: ISSUE-019; GitHub #13
- First observed: 2026-07-24
- Affected versions: app 1.0.3 (8), asset 2026.07.23.6, commit `0ca2b518d5a079ace1ef1e6d9a6892a5259b080e`
- Fixed versions: none
- Regression test: QA probe only; B5 will add the product test
- Automated evidence: QA root `Assets/CatAtWork/qa/b1-current-build-0ca2b518`; scope digest `597724984b6ea09646c98b8630ce14675c9542ecf25a1046442172e45442f56f`
- Device evidence: clean native run produced privacy-minimized action trace `native-action-trace.jsonl`; active displays were 60 Hz and 120 Hz

## Preconditions

Compile the probe with the exact `Sources/CatAtWorkCore` sources and current
manifest. Record, on every display sample, active action, displayed animation,
frame, root position, velocity, entry source, latest decision source and
refresh rate.

## Reproduction

1. Compile `runtime-probe.swift` with
   `swiftc -parse-as-library -enable-bare-slash-regex Sources/CatAtWorkCore/*.swift Assets/CatAtWork/qa/b1-current-build-0ca2b518/runtime-probe.swift -o /private/tmp/catatwork-b1-runtime-rerun`.
2. Run it against the exact manifest and package digest at both 60 and 120 Hz.
3. Cover preview walk/run, pointer walk/chase, shoo left/right, autonomous
   walk/run and left/right deceleration.
4. Flag any walk/run interval lasting at least 100 ms with |vx| < 8.

## Expected

Outside a bounded start/stop transition, locomotion animation has matching
directional velocity and accumulated root displacement at both refresh rates.

## Actual

Preview walk and run each hold a locomotion action at zero displacement for
**2.9 s** at both refresh rates. Shoo produces **1.35–1.358 s** near-zero
locomotion windows; deceleration leaves locomotion active at zero for **1.0
s**. Pointer and autonomous steady-state paths move, with their synchronized
samples retained in the same trace. The clean native log independently
contains repeated walk/run activations at `velocityX = 0`.

## Root cause

Confirmed current control path: preview explicitly zeroes velocity before
forcing a locomotion action; queued shoo/pointer actions can outlive their
motion window; animation time advances independently of root distance.

## Impact

The same locomotion assets can move correctly or visibly run in place depending
on entry path and queue timing.

- 2026-07-24: all required entry paths sampled at 60/120 Hz; classified
  `current-confirmed`.

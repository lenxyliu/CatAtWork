# BC-003 — Pet switch inherits prior session transient state

- Status: fixed
- ISSUE: ISSUE-002
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-011 (release pending)
- Regression test: `testIncompletePhysicalChainIsUnavailableAndCoreSessionStartsFresh`
- Automated evidence: TR-PACKAGE-20260723-002; independent App source typecheck
- Device evidence: package-switch visual acceptance remains a release audit item

## Preconditions

The first pet is moving, queued, airborne, or has pointer/autonomy timers when another package is selected.

## Reproduction

Call `loadPet(at:)` while the prior session has non-default behavior, player, physics or interaction state.

## Expected

The new pet begins an atomic fresh session at idle with empty queue, reset pose/time/velocity/interaction and a new cache namespace.

## Actual

Only manifest/root/layout/player transition are replaced; behavior, physics and many controller timers survive.

## Root cause

Session identity is not modeled and runtime state is spread across controller fields.

## Impact

Wrong animation, speed, posture, drag ownership or delayed behavior can leak into another pet.

## Status timeline

- 2026-07-23: opened from load-path review.
- 2026-07-23: enumerated inherited controller state and started an atomic
  post-validation session reset on `codex/pet-package-contract`.
- 2026-07-23: fixed by reset-by-replacement for core state plus centralized
  controller reset of animation, physics, drag, pointer, gaze, roam, deferred
  event and renderer namespace state; verified by TR-PACKAGE-20260723-002.

# BC-003 — Pet switch inherits prior session transient state

- Status: open
- ISSUE: ISSUE-002
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: none
- Regression test: package switch performs complete session reset
- Automated evidence: pending
- Device evidence: pending

## Preconditions

The first pet is moving, queued, airborne, or has pointer/autonomy timers when another package is selected.

## Reproduction

Call `loadPet(at:)` while the prior session has non-default behavior, player, physics or interaction state.

## Expected

The new pet begins an atomic fresh session at idle with empty queue, reset pose/time/velocity/interaction and a new cache namespace.

## Actual

Only manifest/root/layout/player transition are replaced; behavior, physics and many controller timers survive.

## Root cause

Session identity is not modeled and runtime state is spread across controller fields.

## Impact

Wrong animation, speed, posture, drag ownership or delayed behavior can leak into another pet.

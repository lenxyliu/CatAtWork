# BC-113 — Right-click menu depends on a monitor race

- Status: device-pending
- ISSUE: ISSUE-113
- First observed: before 2026-07-23
- Affected versions: legacy global-monitor menu path
- Fixed versions: 2026-07-23 frozen workspace claim
- Regression test: direct view right-click path with permission allow/deny
- Automated evidence: frozen ISSUE-CLASSIFICATION section 3
- Device evidence: pending permission matrix

## Preconditions
The transparent window is currently passing mouse events through.
## Reproduction
Right-click while a global monitor attempts to make the window hittable.
## Expected
The view handles right-click deterministically and pauses gestures while menu is open.
## Actual
Menu availability varies with monitor/window timing.
## Root cause
The former implementation relied on an asynchronous global-listener race.
## Impact
Core controls such as scale/settings are intermittently inaccessible.
## Status timeline
- 2026-07-23: migrated; direct view handler claimed, permission/device evidence pending.

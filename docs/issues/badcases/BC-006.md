# BC-006 — Frame texture loading has no bounded asynchronous cache

- Status: fixed
- ISSUE: ISSUE-003
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-012
- Regression test: repeat hit, in-flight coalescing, byte-limit eviction and session invalidation
- Automated evidence: TR-IO-20260723-004, TR-IO-20260723-006
- Device evidence: pending

## Preconditions

Play image-per-frame packages repeatedly or switch among large atlases.

## Reproduction

Render repeated frames while observing disk decode calls, main/display callback timing, and retained memory.

## Expected

Texture loads are asynchronous, identical in-flight requests coalesce, hits avoid disk/decode, and LRU eviction enforces a byte ceiling per session namespace.

## Actual

Texture/resource work lacks a documented bounded cache boundary and can repeat synchronous load work or retain uncontrolled resources.

## Root cause

Rendering owns resource lookup without a separate cache policy abstraction.

## Impact

Frame stalls and memory growth on high-frame custom packages.

## Status timeline

- 2026-07-23: opened from renderer review.
- 2026-07-23: implementation started on `codex/background-asset-io`;
  async load publication, coalescing, byte-bounded eviction and session
  invalidation are tracked by CHG-20260723-012 and ADR-0013.
- 2026-07-23: fixed after hit/coalescing, decoded-byte LRU, non-cancelling
  late-result invalidation and full-suite regressions passed in
  TR-IO-20260723-004.
- 2026-07-23: returned to fixed-unverified because Xcode 16.4 rejected
  transferring the raw main-actor `MTLDevice` into the cache actor; failure
  preserved in TR-IO-20260723-005.
- 2026-07-23: fixed by constructing the reviewed sendable Metal device
  wrapper before the actor boundary; final local verification is
  TR-IO-20260723-006 and hosted rerun remains the PR merge gate.

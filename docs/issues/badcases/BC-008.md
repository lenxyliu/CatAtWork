# BC-008 — History cleanup can destroy the only old artwork copies

- Status: in-progress
- ISSUE: ISSUE-005
- First observed: 2026-07-23
- Affected versions: local prehistory repository
- Fixed versions: none
- Regression test: archive integrity, manifest hash and Release round-trip
- Automated evidence: TR-RECOVERY-20260723-001 (local partial); remote round-trip pending
- Device evidence: not applicable

## Preconditions

The unborn repository has 2+ GiB of loose Git objects and dangling/Codex snapshot trees, while old art states are not on a remote.

## Reproduction

Run garbage collection/pruning or replace `.git` before extracting and validating unique Assets trees.

## Expected

Every unique historical state and DMG is externally archived, checksummed, uploaded and re-downloaded before exact approved cleanup.

## Actual

Before recovery, object storage was the only copy of several historical action-art states and build output mixed evidence with disposable files.

## Root cause

Repeated binary snapshots in an unborn repository without LFS, remote backup or artifact policy.

## Impact

Irrecoverable loss or a permanently multi-gigabyte source repository.

## Status timeline

- 2026-07-23: old `.git` frozen outside workspace; nine unique Assets trees exported and locally ZIP-validated.
- 2026-07-23: seven historical DMGs copied outside the workspace and source/copy SHA-256 matched.
- 2026-07-23: private Release upload and download verification still pending; no deletion authorized.

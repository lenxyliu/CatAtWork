# BC-013 — Unmerged evidence records are frozen before acceptance

- Status: fixed
- ISSUE: ISSUE-010
- First observed: local pre-push after commit cd3395d on 2026-07-23
- Affected versions: baseline governance through commit cd3395d
- Fixed versions: `codex/ci-swift6-baseline`
- Regression test: protected-base records reject M/D while branch-new records permit refinement
- Automated evidence: TR-CI-20260723-003
- Device evidence: not applicable to repository governance

## Preconditions

A PR contains a CHG and passing TR from an earlier commit. A later commit
changes governed content and creates a new passing TR before the branch has
merged into protected `main`.

## Reproduction

Commit the later governed change, update the earlier branch-local CHGs to link
the fresh TR, then run the pre-push check against `origin/main`.

## Expected

Records that exist only in the unmerged PR may be refined. Records already
accepted in the PR base remain immutable and must be superseded.

## Actual

The checker rejected every modified ADR, CHG, TR or audit solely because its
aggregate diff status was not `A`, even when the path did not exist in
`origin/main`. The push then failed because older CHGs could not be updated to
link the new digest-matched TR.

## Root cause

Immutability was inferred from diff status instead of membership in the
protected base tree. A staged modification reports `M` regardless of whether
the record has ever entered `main`.

## Impact

Compliant multi-commit PRs deadlock: executable changes invalidate earlier
TRs, while the gate prohibits adding the replacement TR link required to
restore freshness.

## Status timeline

- 2026-07-23: pre-push after `cd3395d` rejected CHG-002 and CHG-003 as stale.
- 2026-07-23: introduced protected-ref lookup and two lifecycle regression
  fixtures; all 12 governance tests passed.
- 2026-07-23: staged validation against `origin/main` accepted refinements to
  branch-only records while preserving accepted-record immutability.

# BC-005 — Large import can freeze UI or deadlock on a full process pipe

- Status: fixed
- ISSUE: ISSUE-003
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-012
- Regression test: large archive import keeps main actor responsive and drains both pipes
- Automated evidence: TR-IO-20260723-004
- Device evidence: pending

## Preconditions

Import a large or malformed compressed package that produces enough process output or expensive file/image validation.

## Reproduction

Start import from the UI and exercise the unzip/process path while output exceeds pipe capacity.

## Expected

Extraction and validation run off-main, stdout/stderr drain concurrently, cancellation/limits work, and UI remains responsive.

## Actual

Synchronous work is reached from main-actor flows and waiting for process termination before draining pipes can block indefinitely.

## Root cause

No explicit asynchronous import boundary and unsafe `Process` pipe ordering.

## Impact

Application beachball, deadlock, and denial-of-service through an imported package.

## Status timeline

- 2026-07-23: opened from importer/store review.
- 2026-07-23: implementation started on `codex/background-asset-io`;
  process draining, import limits and a main-actor responsiveness regression
  are tracked by CHG-20260723-012 and ADR-0013.
- 2026-07-23: fixed after a 4 MB combined-output regression, background
  executor probe, process timeout/cancellation tests, safe ZIP installation,
  traversal/symlink rejection smokes and the full 53-test suite passed in
  TR-IO-20260723-004.

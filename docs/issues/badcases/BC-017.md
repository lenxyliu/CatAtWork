# BC-017 — Main push treats all accepted history as newly added

- Status: fixed
- ISSUE: ISSUE-014
- First observed: local merge preflight on 2026-07-23
- Affected versions: workflow at branch commit 4f2a62e
- Fixed versions: `codex/ci-swift6-baseline`
- Regression test: push workflow uses github.event.before and contains no --all invocation
- Automated evidence: TR-CI-20260723-005
- Device evidence: not applicable to GitHub governance

## Preconditions

The repository contains accepted baseline CHG/design/TR history and a PR adds
new strategic CHGs with a newer governed-content digest.

## Reproduction

Run `python3 Scripts/check_governance.py --all` on the final PR tree, matching
the old push-to-main workflow.

## Expected

The post-merge push validates only paths introduced by the merge against the
previous `main` commit.

## Actual

Every historical path is represented as `A`. CHG-001 is incorrectly required
to reference the latest digest, and each new strategic CHG is incorrectly
required to appear in every design document in the repository.

## Root cause

The initial-baseline `--all` mode was reused for every push to `main` instead
of diffing the pushed commit against `github.event.before`.

## Impact

The PR could be fully green but its squash merge would immediately make the
authoritative main workflow red for immutable historical records that were
not changed.

## Status timeline

- 2026-07-23: merge preflight reproduced the deterministic false failures.
- 2026-07-23: push workflow switched to the exact before SHA and a workflow
  contract regression test was added.

# BC-004 — Transparent canvas intercepts input without collision metadata

- Status: fixed
- ISSUE: ISSUE-002
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-011 (release pending)
- Regression test: `testPackageScaleNormalizesPixelDensityAndInteractionUsesTrimFallback`
- Automated evidence: TR-PACKAGE-20260723-002
- Device evidence: pointer passthrough remains part of release-candidate acceptance

## Preconditions

Render a trimmed frame whose `collisionRect` is absent and source canvas contains transparent margins.

## Reproduction

Move/click inside the transparent canvas but outside `trimRect`.

## Expected

The desktop receives input; only visible body bounds participate in fallback hit testing.

## Actual

Fallback uses the entire window/canvas and transparent pixels can intercept desktop interaction.

## Root cause

Renderer/controller fallback is not aligned with the manifest's trimmed geometry.

## Impact

Invisible click-blocking regions and inconsistent pet gestures.

## Status timeline

- 2026-07-23: opened from hit-test review.
- 2026-07-23: confirmed `interactiveFrame` returns the entire window when
  collision metadata is absent; trim-bound regression implementation started.
- 2026-07-23: fixed with the single `collisionRect ?? trimRect` interaction
  geometry contract used by the controller; verified by
  TR-PACKAGE-20260723-002.

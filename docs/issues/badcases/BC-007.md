# BC-007 — Window controller is a second runtime state machine

- Status: fixed
- ISSUE: ISSUE-004
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-014
- Regression test: reducer plus App adapter integration suite
- Automated evidence: TR-RUNTIME-20260723-002
- Device evidence: pending

## Preconditions

Combine autonomy, pointer, system and physical events while changing session or display state.

## Reproduction

Trace ownership of pose, queue, player, physics, timers, roaming, gaze and interaction fields across `BehaviorEngine` and `PetWindowController`.

## Expected

One deterministic `PetRuntimeState` and reducer decide transitions; controller only translates inputs and applies effects.

## Actual

Dozens of controller fields form implicit coupled state that cannot be reset or integration-tested atomically.

## Root cause

Runtime behavior accumulated directly in the AppKit controller.

## Impact

State drift, incomplete reset, difficult regression testing and high change risk.

## Status timeline

- 2026-07-23: opened from architecture review.
- 2026-07-23: implementation started on `codex/runtime-controller-split`; the
  core session reducer and controller adapter boundary are tracked by
  CHG-20260723-014 and ADR-0014.
- 2026-07-23: fixed after 57 Swift tests, focused reducer/animation/physics
  regressions, app build and independent validation passed in
  TR-RUNTIME-20260723-002. Real-device integration remains release audit work.

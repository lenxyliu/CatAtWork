# BC-021 — Current-build root-relative body and support instability

- Status: open
- Classification: current-confirmed
- ISSUE: ISSUE-018; GitHub #12
- First observed: 2026-07-24
- Affected versions: app 1.0.3 (8), asset 2026.07.23.6, commit `0ca2b518d5a079ace1ef1e6d9a6892a5259b080e`
- Fixed versions: none
- Regression test: not implemented; B2/B3 will define stable root/support gates
- Automated evidence: QA root `Assets/CatAtWork/qa/b1-current-build-0ca2b518`; scope digest `8bd809b0c8703caf093ce616893044c7221cf7067b3486f69e242ec09363c244`
- Device evidence: fixed-root runtime canvas and native animation inspected

## Preconditions

Render current frames at an invariant world root using each manifest pivot and
render offset. Measure the alpha centroid relative to that root; do not infer
motion from the per-frame crop origin.

## Reproduction

1. Build current previews and preserve `previews/runtime-canvas.json`.
2. Place each crop on the 665×737 root-aligned canvas.
3. Calculate adjacent centroid displacement and inspect `happy`, `failed`,
   `runLeft` and `bellyPet`.
4. Confirm the package pivots are derived per frame from changing crop
   geometry rather than an authored anatomical root.

## Expected

Non-semantic root-relative drift stays within 1 authoring pixel; support
movement must be declared as action semantics.

## Actual

Root-aligned centroid jumps reach **39.678 px** in `happy` and **34.709 px**
in `failed`; the full scan reaches **53.596 px** at `runLeft` 20→21.
Per-frame pivot pixel coordinates also move with each crop.

## Root cause

Confirmed implementation/content boundary: the manifest carries a different
alpha-derived pivot per crop and no authored stable anatomical root/support
track. Which individual motion pixels should remain after a future repair is a
B3 decision.

## Impact

Normal outline changes can move the apparent body relative to the world root,
producing floating, sinking or screen-space jitter.

- Status: open
- Classification: current-confirmed
- ISSUE: ISSUE-016; GitHub #10
- First observed: 2026-07-24
- Affected versions: app 1.0.3 (8), asset 2026.07.23.6, commit `0ca2b518d5a079ace1ef1e6d9a6892a5259b080e`
- Fixed versions: none

- Automated evidence: QA root `Assets/CatAtWork/qa/b1-current-build-0ca2b518`; scope digest `dc8d31d01a3f2e8e848bf6fdde62ce73e60085536c210b7d4c081275646e2c4e`
- Device evidence: native app and content-matched action sheets inspected; no phone exposure evidence used

## Preconditions

Use the exact current default package and sRGB atlas pixels. Partition visible
pixels into light, warm and dark material samples; do not measure the desktop
background.

## Reproduction

1. Generate current contact sheets with `Scripts/build_previews.py`.
2. At alpha ≥ 12, convert the three material partitions to Lab and calculate
   adjacent-frame CIEDE2000 distance.
3. Inspect `happy`, `runRight` and `idle` side by side.

## Expected

Comparable adjacent material regions remain at ΔE00 ≤ 3, and no isolated
frame exceeds the Issue budget.

## Actual

`happy` frames 2→3 measure light-fur ΔE00 **5.1523** and warm-fur ΔE00
**4.2466**. The same sequence contains multiple visibly different scale/color
groups. These values come from current RGBA assets, not camera exposure.

## Root cause

Confirmed failure scope: color differences are present in the content-matched
atlas pixels. Whether they came from generation batches, grading or later
editing remains unverified.

## Impact

The character appears to change coat or lighting inside a single action,
amplifying geometry and identity jumps.

## Status timeline

- 2026-07-24: current RGBA evidence exceeded the Issue thresholds; classified
  `current-confirmed`.

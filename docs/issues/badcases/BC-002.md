# BC-002 — Missing `.catpet` actions silently become idle

- Status: fixed
- ISSUE: ISSUE-002
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-011 (release pending)
- Regression test: `testExactLookupAndSemanticFallbackNeverSilentlyUseIdle`
- Automated evidence: TR-PACKAGE-20260723-002
- Device evidence: not required for deterministic resolution; unavailable UI state remains in release acceptance

## Preconditions

Load a valid package that supplies `idle` but omits a runtime-hardcoded optional action.

## Reproduction

Trigger the omitted behavior and resolve it through `PetManifest.animation(named:)`.

## Expected

The package declares the capability unavailable and runtime chooses a documented semantic fallback or suppresses the behavior.

## Actual

The lookup silently returns `idle`, masking contract mismatch and potentially corrupting pose/completion state.

## Root cause

Animation lookup combines exact resolution with fallback and runtime assumes a fixed action vocabulary.

## Impact

Custom pets behave unpredictably and package validation cannot explain missing capabilities.

## Status timeline

- 2026-07-23: opened from contract review.
- 2026-07-23: implementation started on `codex/pet-package-contract`;
  exact lookup, semantic fallback and suppression regressions pending.
- 2026-07-23: fixed with exact manifest lookup, documented fallback chains,
  `.ignoredUnavailable` suppression and capability-gated settings/preview UI;
  verified by TR-PACKAGE-20260723-002.

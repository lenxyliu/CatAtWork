# BC-011 — Dot-prefixed governance files do not invalidate stale test evidence

- Status: fixed
- ISSUE: ISSUE-008
- First observed: 2026-07-23 while validating CHG-20260723-002
- Affected versions: baseline commit 856511e86b060979409fde02d8d8d4a98215751b
- Fixed versions: `codex/ci-swift6-baseline`, governed digest b7d463ec4d7c7800b17a6a8dcb04250da0cc7e5341d26d7096c34ed8848e7371
- Regression test: normalization preserves dot-prefixed repository paths and workflow creation/update changes the governed digest
- Automated evidence: TR-CI-20260723-001
- Device evidence: not applicable to governance hashing

## Preconditions

A governed path starts with a dot, such as `.github/workflows/ci.yml`,
`.githooks/pre-push`, `.gitignore` or `.gitattributes`.

## Reproduction

Change `.github/workflows/ci.yml` and run
`python3 Scripts/check_governance.py digest`.

## Expected

The digest changes, so every older TR becomes stale.

## Actual

The digest remains unchanged because normalization converts `.github/...` to
`github/...`, which no longer matches the configured governed prefix.

## Root cause

`str.lstrip("./")` removes every leading period or slash character rather
than removing only the literal relative-path prefix `./`.

## Impact

Hooks, CI workflows and root governance dotfiles could change after a passing
test while the old TR still appeared fresh, undermining the mandatory
traceability gate.

## Status timeline

- 2026-07-23: detected because the CI workflow changed but the digest did not.
- 2026-07-23: replaced character-set stripping with literal `./` removal;
  all 10 governance fixtures passed and the corrected digest changed.

# BC-016 — Private main cannot be protected on the current GitHub plan

- Status: blocked-external
- ISSUE: ISSUE-013
- First observed: GitHub branch-protection API on 2026-07-23
- Affected versions: private `lenxyliu/CatAtWork` under GitHub Free
- Fixed versions: none
- Regression test: main protection API reports required PR/checks and rejects force-push/deletion
- Automated evidence: TR-GITHUB-20260723-001
- Device evidence: not applicable to repository hosting policy

## Preconditions

`lenxyliu/CatAtWork` is a private repository owned by a personal GitHub Free
account.

## Reproduction

Read or update
`repos/lenxyliu/CatAtWork/branches/main/protection` with an authenticated
repository-owner token.

## Expected

`main` requires PRs plus `governance` and `swift`, and disallows direct
pushes, force-pushes and deletion.

## Actual

GitHub returns HTTP 403: upgrade to GitHub Pro or make the repository public
to enable the feature.

## Root cause

GitHub exposes protected branches and rulesets for private repositories only
on paid personal/organization plans. The repository intentionally remains
private, and billing changes require the owner's explicit action.

## Impact

Checks and squash-only repository settings work, but GitHub cannot prevent an
owner credential from pushing directly to `main`. The planned enforcement
gate is incomplete, so PR #1 is ready but not merged.

## Status timeline

- 2026-07-23: protection read/update returned HTTP 403.
- 2026-07-23: squash-only merge and post-merge branch deletion were enabled.
- 2026-07-23: documented merge pause pending an explicit owner decision on
  GitHub Pro versus repository visibility; no billing or visibility mutation
  was attempted.

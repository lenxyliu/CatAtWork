# BC-001 — Priority queue breaks an enqueue-time pose chain

- Status: fixed
- ISSUE: ISSUE-001
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: CHG-20260723-010 (release pending)
- Regression test: `testQueuedIntentReroutesFromActualPoseAndSelectedPlanIsAtomic`
- Automated evidence: TR-ACTION-20260723-001
- Device evidence: not required for deterministic core queue semantics; visual acceptance remains a release audit item

## Preconditions

The current action has a known pose and two later intents require different poses/priorities.

## Reproduction

Queue a low-priority behavior whose pose bridge is expanded immediately, then queue a higher-priority behavior. Finish the current animation and let `ActionCoordinator` reorder individual queued actions.

## Expected

The selected intent receives a bridge computed from the actual pose at dequeue, and no action starts from an incompatible pose.

## Actual

Bridge and target are independent queue entries; priority ordering can separate them or run a bridge intended for another successor.

## Root cause

Transition expansion occurs before the coordinator has selected the next intent.

## Impact

Visible snapping, illegal posture chains, or an incorrect final pose under mixed inputs.

## Status timeline

- 2026-07-23: reproduced by code-path review; opened.
- 2026-07-23: isolated a deterministic chain: while standing, queue a
  low-priority walk, then a higher-priority seated wave. The wave changes the
  actual pose to seated before the earlier walk is selected, so enqueue-time
  routing starts walking without `sitToStand`.
- 2026-07-23: implementation started on `codex/action-state-machine`;
  verification pending.
- 2026-07-23: fixed by raw-intent queuing, actual-pose activation routing
  and atomic continuation ownership. TR-ACTION-20260723-001 passed 38 Swift
  tests, including explicit-finish, timed-expiry and force-clear regressions.

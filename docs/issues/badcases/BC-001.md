# BC-001 — Priority queue breaks an enqueue-time pose chain

- Status: open
- ISSUE: ISSUE-001
- First observed: 2026-07-23
- Affected versions: pre-governance main
- Fixed versions: none
- Regression test: mixed-priority queue preserves legal pose chain
- Automated evidence: pending
- Device evidence: pending

## Preconditions

The current action has a known pose and two later intents require different poses/priorities.

## Reproduction

Queue a low-priority behavior whose pose bridge is expanded immediately, then queue a higher-priority behavior. Finish the current animation and let `ActionCoordinator` reorder individual queued actions.

## Expected

The selected intent receives a bridge computed from the actual pose at dequeue, and no action starts from an incompatible pose.

## Actual

Bridge and target are independent queue entries; priority ordering can separate them or run a bridge intended for another successor.

## Root cause

Transition expansion occurs before the coordinator has selected the next intent.

## Impact

Visible snapping, illegal posture chains, or an incorrect final pose under mixed inputs.

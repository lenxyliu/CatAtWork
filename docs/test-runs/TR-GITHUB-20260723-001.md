## Tested content

Merge methods, post-merge branch cleanup and availability of server-enforced
protection for `main` in private `lenxyliu/CatAtWork`.

## Commands

```sh
gh api repos/lenxyliu/CatAtWork
gh api repos/lenxyliu/CatAtWork/branches/main/protection
gh api --method PATCH repos/lenxyliu/CatAtWork \
  -F allow_squash_merge=true \
  -F allow_merge_commit=false \
  -F allow_rebase_merge=false \
  -F delete_branch_on_merge=true
```

## Passed

- Repository visibility remained `private`.
- `allow_squash_merge` is `true`.
- `allow_merge_commit` and `allow_rebase_merge` are `false`.
- `delete_branch_on_merge` is `true`.
- The authenticated GitHub CLI and repository-scoped SSH deploy key operate
  independently of the browser login session.

## Failed

Reading or enabling `main` protection returned HTTP 403 with GitHub's
instruction to upgrade to GitHub Pro or make the repository public.

## Skipped

No billing-plan change, visibility change or unprotected merge was attempted.
Required checks could not be attached to branch protection because the
feature itself is unavailable.

## Failure analysis

Authentication and repository ownership are valid; other settings updated
successfully. GitHub's documented plan matrix and the API message both
identify account tier/private visibility as the sole blocker.

## Evidence

- Repository: `https://github.com/lenxyliu/CatAtWork`.
- PR checks: `https://github.com/lenxyliu/CatAtWork/actions/runs/29985577013`.
- GitHub documentation states that private-repository protected branches and
  rulesets require Pro, Team or Enterprise.
- Exact HTTP 403 output is preserved in the Codex task.

## Retrospective

CI success and branch enforcement are separate claims. Testing the settings
before merging prevented a green PR from being mistaken for a protected
workflow and avoided an unauthorized visibility or billing change.

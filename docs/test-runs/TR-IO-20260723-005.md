## Failure analysis

The implementation wrapped `MTLDevice` in `@unchecked Sendable` only inside
the destination actor initializer. Swift 6.1 therefore diagnosed the raw
framework existential crossing from the main-actor view into the cache actor
before that wrapper existed. Local Xcode 26.6 accepted the same source, so only
the hosted compatibility build exposed the boundary.

The fix must construct the reviewed sendable wrapper on the main actor and
pass that wrapper—not raw `MTLDevice`—across the actor boundary. Metal devices
are designed for concurrent resource creation; the wrapper documents that
framework-level guarantee without making other Metal resources sendable.

## Retrospective

An unchecked-sendable adapter must exist before a legacy framework object
crosses isolation. Wrapping only after actor entry cannot satisfy an older
Swift 6 region-isolation checker even when a newer local toolchain accepts it.

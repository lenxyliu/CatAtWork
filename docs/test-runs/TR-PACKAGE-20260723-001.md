## Failure analysis

`previewAnimation` used `force=true`. ActionCoordinator correctly cleared the
old queue for forced replacement, but forced replacement also bypassed the
planner, coupling two unrelated policies. The package pose graph was correct;
the preview path never consulted it.

## Retrospective

Queue replacement and pose safety are separate decisions. Preview needs the
former but not the latter; physical grab/throw needs immediate ownership and
may intentionally use a direct forced transition. The coordinator API must
allow the caller to choose a planner for forced replacement rather than
globally treating all force as a pose bypass.

## Failed

The coalescing case made two concurrent requests with different sentinel
values, then asserted that the lexically first `async let` must win. Scheduling
started the second request first, so both waiters correctly received the second
sentinel and the cache hit did too. Two assertions failed.

## Skipped

Full tests and final validation were not run after the focused failure.

## Failure analysis

The cache promises one shared result, not source-order ownership between
concurrent callers. The observed identical results demonstrate coalescing; the
test incorrectly coupled it to nondeterministic task scheduling.

## Evidence

- Seven executed, two assertion failures in
  `testCacheHitsAndCoalescesConcurrentLoads`.
- All other focused cases passed.
- Output is retained in the 2026-07-23 Codex task.

## Retrospective

Concurrency regressions must assert invariants: both values equal, one loader
execution, one miss and one coalesced request. They must not assign semantic
meaning to which concurrent task reaches an actor first.
